Workspace layout

<workspace>/
  sources/<record-id>/
    source.original.<extension>
    source.txt
    source-manifest.json
  artifacts/<record-id>/
    yammerknit.md
    artifact-manifest.json
    validation.json
  revisions/<record-id>/<revision-id>/
    yammerknit.md
    revision-manifest.json
    validation.json

Manifests record relative filenames and hashes, so the complete workspace can move without breaking its internal references.

What custody means

Helpers create new records and revisions, preserving existing ones. Inspection reads actual bytes, checks hashes and receipt agreement, and follows one complete parent chain. Missing or contradictory evidence prevents current selection. Historical records lacking a source binding remain labeled as such.

Hashes establish consistency with manifests, not signed authenticity, source truth or proof that an author read the material. Coordinated changes require a separately trusted digest or backup to detect. Workspaces are intended to be controlled by their user, not protected against a hostile concurrent filesystem actor.

Network and private data

The core helper includes no telemetry or cloud store. The agent host can send supplied material to its configured model/provider. User documents and metadata may themselves contain private information. Optional subtitle acquisition invokes separately installed yt-dlp and contacts YouTube. A local command is not automatically offline.

Minimize material before sharing logs, publishing or using remote embeddings. Installing the package does not upload existing workspaces.

You choose the destination

You choose the workspace and any later transfer, embedding, backup, or publication destination. Installing Yammerknit does not upload existing records.

Before sharing support evidence: remove private source content, credentials, and unrelated personal data from logs and receipts.
