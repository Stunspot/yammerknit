Current checks and historical evidence

The restoration uses isolated custody counterexamples, a complete fictional source task, package extraction/rebuild and bounded site navigation. These checks cover specific mechanisms. Expert authored continuations are not executed model trials.

Older live-invocation, canary and release-audit records describe earlier bytes. They do not certify this candidate merely because both display version 0.1.0. Current candidate evidence is retained in the repository's verification/estate-quality-20261007/ directory.

Interpret and reproduce a check

Artifact validation checks structure and bridge consistency. Record inspection checks stored bytes and ancestry. Neither checks source entailment, authorship or retrieval benefit.

From an extracted customer root:

python source/verification/audit_release.py --root .
python source/verification/build_release.py --repo source --output-dir "NEW-OUTPUT-DIRECTORY"

The audit reports inventory/hash/runtime mismatches. The rebuild uses the included bounded source closure; compare its ZIP digest with the original. Choose a nonexistent output directory outside the kit. Help is read-only, and audit output cannot overwrite the package.

Limits

No new host-model trial, live Claude activation, retrieval benchmark, live caption-acquisition test or assistive-technology conformance assessment is claimed for this repair. The helper has no embedding model, vector store or retrieval runtime. Transcript extraction cannot establish unseen visual evidence. The underlying agent may still make semantic errors; review consequential reuse against the source.

Inspect the machinery: open the public verification directory. Propose a change: read the contribution guide.
