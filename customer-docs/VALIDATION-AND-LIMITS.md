# What validation establishes

`validate` checks the artifact's required structure, resolvable bridge endpoints, bridge fields, fence integrity and sigil coverage. It does not determine whether a claim follows from its source. `inspect-record` checks actual stored bytes, receipts, source binding when recorded and a complete revision chain. It does not authenticate coordinated changes or certify model authorship.

The current restoration is exercised with isolated synthetic records, corruption and path counterexamples, the supplied fictional source task, package extraction/rebuild, and bounded documentation navigation. These checks are useful evidence for those mechanisms. Expert continuation comparisons are authored reviews, not executed model trials. The repair contains no new host-model trial, live Claude activation, retrieval benchmark or assistive-technology conformance assessment.

Repository `verification/estate-quality-20261007/` retains the pre-repair failures, current task evidence and exact candidate inventory. Older `verification/live-invocation-*`, `final-live-canary.json` and `release-audit.json` remain historical observations about earlier bytes. They do not certify this repaired candidate merely because it also displays 0.1.0.

## Check a customer kit

From the extracted customer root, run:

```text
python source/verification/audit_release.py --root .
```

Zero issues means the selected tree matches its declared inventory and its nested Claude runtime agrees with the Codex runtime. Hashes supplied alongside a package check consistency, not independently trusted publisher identity. To reproduce the package from its bounded included source closure, choose a nonexistent directory outside the kit and run:

```text
python source/verification/build_release.py --repo source --output-dir "NEW-OUTPUT-DIRECTORY"
```

Compare the resulting ZIP SHA-256 with the original kit's checksum. No live user workspace is part of this rebuild. `--help` on both commands performs no build or receipt write. The public documentation site is maintained separately in the repository and is not an archive browser or retrieval runtime.

## Limits that matter in use

The optional subtitle backend is separately installed software and live acquisition depends on accessible captions. A transcript does not prove unseen visual details or caption accuracy. Yammerknit includes no embeddings, vector database or retrieval execution. Evaluate any proposed retrieval improvement on the actual pipeline and likely questions, including misleading-answer and unanswerable cases.
